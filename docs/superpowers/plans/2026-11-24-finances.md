# Finances (💰 Treasury) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import weekly BCA "mutasi rekening" PDFs and show a 50/30/20 budget per allowance cycle (bars, donut, payments list, balance) in a new 💰 Treasury tab, plus real numbers in the Profile money slot.

**Architecture:** `pdftotext -layout` turns a PDF into text (`src/pdf-text.js`, the only file that runs a program). Three pure modules do all the rules: `src/bca-parse.js` (text → rows), `src/merchant.js` (row → merchant key), `src/finance.js` (duplicates, refunds, cycles, totals, balance). `src/db.js` stores rows, imports and merchant labels. `src/ipc.js` joins them, and `ui/treasury.js` only draws what it is sent.

**Tech Stack:** Electron 45, Node 22 `node:sqlite`, `node:child_process.execFile`, `node --test`, plain CommonJS and DOM (no frameworks).

**Spec:** `docs/superpowers/specs/2026-11-24-finances-design.md`

## Global Constraints

- Plain CommonJS, no frameworks, no new npm dependencies, "why" comments a beginner can follow.
- **Money is always an integer number of sen** inside the app (`50,000.00` → `5000000`). Only the window formats it as rupiah.
- **No real bank data in the repo.** Test fixtures use made-up names and the fake card number `1234567812345678`. Never read `~/Downloads` in tests.
- Card numbers (`\d{16}`, with an optional `/Y` after them) are removed from `text` before saving. The header's account number and name are never saved.
- Schema version **4**. Existing databases just gain the new tables. Data already stored must survive.
- Split: Needs **50%**, Wants **30%**, Save **20%** of the pot, as named constants in `src/finance.js`.
- Settings: `allowanceMin` default **200000000** (2,000,000 rupiah), `balanceAnchor` default **null** (`{ date, amount }` once set).
- A second allowance within **20 days** of its cycle's start doesn't start a new cycle. A refund matches a payment **0–7 days** before it.
- Duplicate key: **date, amount, direction, merchant key**.
- Labels: `'need' | 'want' | 'skip'`. Kinds: `'spend' | 'refund' | 'income'`. Allowance flag: `null | 1 | 0`.
- Missing pdftotext message, exactly: `Reading PDFs needs pdftotext. Install it with: sudo dnf install poppler-utils`
- Nothing about money is pushed to Google, and nothing about money gives XP.

## Review Focus

- **Two weekly files that share a boundary day, or the same file imported twice:** the second import adds only the rows it hasn't seen, and a re-import adds 0. Three identical same-day charges stay three. Tested in Task 3 (`newRows`) and Task 6 (`re-import adds nothing`).
- **A page break in the middle of a statement:** the repeated header, the "CATATAN" lines and "Bersambung ke Halaman berikutnya" never become rows and never stick to a row's text. Tested in Task 1 (`page break`).
- **A payment fixed by hand, then its merchant relabelled:** the hand-fixed label wins, in every cycle. Tested in Task 4 (`override beats merchant label`).
- **Deleting an import that held one half of a refund pair:** the other half is classified again (it becomes plain `spend` or an unmatched `refund`). Tested in Task 6 (`deleting an import reclassifies`).
- **A wrong file (another bank, a photo saved as PDF, a password PDF) or no pdftotext:** a clear per-file error, nothing saved, and the other files in the same import still go in. Tested in Task 6 (`bad file does not block others`).

**Interfaces:**
- Produces: `parseMutasi(text: string) -> { period: { start: 'YYYY-MM-DD', end: 'YYYY-MM-DD' } | null, rows: Row[], problems: string[] }`
  where `Row = { date: 'YYYY-MM-DD', amount: number /* sen */, direction: 'DB'|'CR', text: string, type: string }`, in the order they appear in the file.
- Produces: `parseAmount('3,200,000.00') -> 320000000`
- Produces from `test/bca-fixture.js`: `WEEK_A` (string, two pages), `WEEK_B` (string, overlaps WEEK_A by one day), `NOT_BCA` (string), and the builders `HEADER(page, pages, period)` and `row(date, desc, amount, dir, ...moreLines)` for tests that need their own statements.

Parsing rules (from spec §5):
- **Row start:** a line matching `^\s*(\d{2})/(\d{2})/(\d{4})\s+(.*?)\s+([\d,]+\.\d{2})\s+(DB|CR)\s*$`. The text between the date and the amount (it may be empty) is the first description line.
- **Continuation lines:** non-empty lines after a row start, up to the next row start, that are indented at least 10 spaces and are not page furniture. The **last** continuation line is `type`. Earlier ones are joined onto the first line to make `text`. `text` has its whitespace squashed to single spaces and is trimmed. If there are no continuation lines, `type` is `''`.
- **Page furniture** (never rows, never continuation lines): lines that start at column 0, and lines whose trimmed text is `MUTASI REKENING` or starts with `Bersambung`. Furniture, and any other non-empty line indented fewer than 10 spaces (such as the `TANGGAL … MUTASI` column header), **ends** the current row's continuation lines.
- **Period:** the first `PERIODE\s*:\s*(\d{2}/\d{2}/\d{4})\s*-\s*(\d{2}/\d{2}/\d{4})`. If there's none, `period` is `null` and `rows` is `[]`.
- **Problems:** a line that starts with an indented `DD/MM/YYYY` but doesn't match the row pattern adds `"Couldn't read the line for DD/MM/YYYY: <trimmed line>"` (cut to 80 characters).

| --- | --- |

| `/^TRN MASTERCARD DBT(.+)$/` | group 1 |

| `/^TRANSFER KE \d+ (.+?) M-BCA$/` | group 1 |
| text is empty | `type` |
| anything else | the whole text |

**Interfaces:**

- Produces: `newRows(fileRows: R[], savedRows: R[]) -> R[]`: for each dup key, let `n` be how many file rows have it and `m` how many saved rows have it. It returns the last `max(0, n − m)` of that key's file rows, keeping file order.
- Produces: `classifyKinds(rows: Txn[]) -> Map<id, 'spend'|'refund'|'income'>`

Refund rule (spec §7.4): a `CR` is a refund when `type === 'KR INTERCHANGE'` or `text` starts with `KOR TRN`. Go through refund CRs from oldest to newest (`date`, then `id`). Every other DB is `spend`, and every other CR is `income`.

### Task 4: Cycles, totals and balance

**Files:**
- Modify: `src/finance.js`
- Test: `test/finance.test.js`

**Interfaces:**
- Consumes: `Txn` with `kind` set (Task 3).
- Produces: `buildCycles(rows: Txn[], allowanceMin: number) -> Cycle[]`, oldest first.
  `Cycle = { start: date, end: date|null /* null = running */, pot: number, allowanceIds: number[], beforeTracking: boolean }`.
  - Candidates: `income` rows with `allowance === 1`, or `allowance === null && amount >= allowanceMin`. Rows with `allowance === 0` are never candidates. Go through them oldest first.
  - A candidate starts a new cycle if there's no cycle yet, or if it is **more than 20 days** after the current cycle's `start`. Otherwise: if `allowance === 1`, it adds to the current `pot` and `allowanceIds`; if it is automatic, it is ignored.
  - Each cycle's `end` = the next cycle's `start` − 1 day. The last one's `end` is `null`.
  - If any row is dated before the first cycle (or there are no candidates at all), add a first cycle `{ start: earliest row date, end: day before first cycle | null, pot: 0, allowanceIds: [], beforeTracking: true }`.
- Produces: `effectiveLabel(row: Txn, merchantLabels: object) -> 'need'|'want'|'skip'|null`: refund → `'skip'`; income → `null`; spend → `row.label ?? merchantLabels[row.merchant] ?? null`.
- Produces: `summarizeCycle(cycle: Cycle, rows: Txn[], merchantLabels: object) -> Summary`:
  ```
  { start, end, beforeTracking, pot,
    limits: { need, want, save },          // Math.round(pot*0.5), Math.round(pot*0.3), pot - need - want
    used:   { need, want, skip },          // spend rows only
    unsorted: { count, amount },
    saved,                                 // pot - every spend row's amount (can be negative)
    moneyIn,                               // income rows' total, allowance included
    payments: [{ ...row, effectiveLabel }] // rows in the cycle, newest first, unsorted spend first
  }
  ```
  A row is in a cycle when `start <= date` and (`end === null` or `date <= end`).
- Produces: `balanceAt(rows: Txn[], anchor: { date, amount }, day: date) -> number` (spec §7.8: `net(a, b]` = CR − DB of rows with `a < date <= b`).
- Produces: `coverage(imports: { periodStart, periodEnd }[]) -> { first, last, gaps: { start, end }[] }`: the days between `first` and `last` that no import covers, as ranges. With no imports, `{ first: null, last: null, gaps: [] }`.

**Interfaces:**
- Produces: `readPdfText(filePath) -> Promise<string>` and `readPdfTextWith(execFileFn) -> (filePath) => Promise<string>` (the same function with `execFile` passed in, for tests) in `src/pdf-text.js`. It uses `execFile('pdftotext', ['-layout', filePath, '-'], { maxBuffer: 20 * 1024 * 1024 })`. On `ENOENT` it rejects with `Error(MISSING_PDFTOTEXT)`, where the message is the Global Constraints text and `code = 'NO_PDFTOTEXT'`. Any other failure rejects with `Error("Couldn't read this PDF: " + stderr-or-message)`. It also exports `MISSING_PDFTOTEXT`.
- `buildHandlers(store, { onChange, clock, extra, readPdfText })`: `readPdfText` defaults to the one in `src/pdf-text.js`. Tests pass a fake.
- Produces these handlers (the window's names, exposed one-to-one in `preload.js`):
  - `async importStatements(paths: string[]) -> { files: [{ fileName, ok, added, known, newMerchants: string[], problems: string[], error? }] }`.
    Per file, in order: read the text, `parseMutasi`. If `period === null`, it fails with `error: "This isn't a BCA mutasi rekening."`. Otherwise it strips card numbers, adds `merchant`, works out `newRows` against `listTransactions()`, then `addImport` with `known = rows − new`. Next comes `newMerchants`: the added DB rows' merchants that aren't in `listMerchantLabels()` and weren't in the database before. One file failing doesn't stop the others. After all files, it runs `classifyKinds(listTransactions())`, then `setKinds`, and calls `onChange()` once if anything was added. `fileName` is the base name only.
  - `getTreasury(index: number | null) -> Treasury`:
    ```
    { hasData, allowanceMin,
      cycles: [{ index, start, end, beforeTracking, pot, used, limits, saved }],   // oldest first, for the All cycles table
      index,                                                                       // the shown one; null → newest
      cycle: Summary | null,                                                       // summarizeCycle of that one
      merchants: { [merchant]: label },
      balance: { anchor, current, asOf, series: [{ date, balance }], gaps } }
    ```
    `asOf` = `coverage(listImports()).last`. `current` = `balanceAt(..., asOf)`, or `null` if there's no anchor. `series` = one point per day from `coverage.first` to `asOf`, but only when there is an anchor.
  - `setLabel(id, label|null)`, `setMerchantLabel(merchant, label)`, `setAllowance(id, 1|0|null)`: check the value against the allowed set and return `{ ok, errors }` through `mutate`.
  - `setBalance({ date, amount })`: `amount` is an integer in sen and `date` is a valid `YYYY-MM-DD`. It saves `balanceAnchor`.
  - `listImports()`, `deleteImport(id)`: after a delete, it reclassifies kinds (as at the end of `importStatements`) and calls `onChange()`.
  - `getMoneySummary() -> null | { spent, moneyIn, balance, asOf }` for the newest cycle (`spent = used.need + used.want + used.skip + unsorted.amount`). It returns `null` when there's no data.
- `main.js` `extra.pickStatements() -> Promise<string[]>`: `dialog.showOpenDialog(mainWindow, { title: 'Import BCA mutasi rekening', properties: ['openFile', 'multiSelections'], filters: [{ name: 'PDF', extensions: ['pdf'] }] })`. It returns `[]` when cancelled.
